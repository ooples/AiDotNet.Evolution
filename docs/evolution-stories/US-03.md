## Scope and versioning

This slice covers the 11-task Python warm program evaluator and its promotion
boundary. It does not certify arbitrary C# execution, every consumer, universal
correctness, or competitive superiority. Existing Docker isolation is reused;
no new privileges are granted and candidate code never executes in a host oracle.

`program_correctness.py` supplies two explicitly named contracts:

- `strict-upstream-v1` (study default): task schema, host mathematical checks,
  **and** pinned upstream acceptance. This is a stricter subset of upstream
  acceptance, not an assertion that the old and new validators are equivalent.
- `mathematical-v1`: the same schema/host checks, but permits mathematically
  equivalent optima without the reference implementation's tie-breaking.
  It is available for explicit evaluation, not silently selected by the study.

For example, a triangle has multiple equal-weight spanning trees. The mathematical
contract accepts alternatives; strict upstream compatibility can reject them.
Output schema, rather than NumPy broadcasting, determines admissible dimensions.
New registrations use `warm-head-to-head-v2` and `both-executables-v1`. Old plans
are refused by the new executor; historical measurements and archives are unchanged.

## Acceptance cases

As a developer using evolved code, I want correctness and final acceptance to be
independent of the candidate's reported speed so that incorrect code cannot win.

| Task | Required result / host check |
|---|---|
| Base64 | Exact bytes in `encoded_data` |
| SHA-256 | Exact digest bytes in `digest` |
| Connected components | Integer count excluding booleans; host union-find |
| Minimum spanning tree | Existing edges/weights, no cycles, spanning-forest size, minimum weight; declared tie policy |
| Dijkstra | Exact matrix dimensions, host heap-based undirected shortest paths; `None` only for unreachable pairs |
| Stable matching | Integer permutation excluding booleans; no blocking pairs |
| Matrix multiplication | Exact matrix shape; host contraction |
| Outer product | Exact matrix shape; host elementwise construction |
| Convolution | Exact full-output vector length; host convolution |
| Correlation | Exact number and lengths of full-output vectors; host correlation |
| Simplex projection | Exact vector shape, nonnegativity, unit sum and optimality conditions |

Numeric comparisons declare `rtol=1e-6`, `atol=1e-8`. Simplex sum tolerance is
`atol+rtol`; its optimality residual scales with the input and threshold.
Strict compatibility additionally applies upstream tolerances. These declared
contracts require verification across supported inputs; they are not proofs of
acceptable error for every consumer. NumPy/hash libraries can share backend
lineage with the reference, so separate host code is not universal oracle independence.

- **Given** a malformed scalar, wrong shape, boolean index, nonfinite result,
  missing field or incorrect value, **when** checked, **then** the result is
  rejected even if an upstream validator would accept it.
- **Given** a valid alternative optimum, **when** checked, **then** mathematical
  correctness and exact upstream compatibility remain explicitly distinguished.
- **Given** hand-written boundary cases and public randomized test instances,
  **when** tests run, **then** both valid and invalid controls are exercised.
  These fixtures are public development evidence, never advertised as untouched
  final performance inputs. Existing sealed study data is not opened.
- **Given** frozen selected code and original code, **when** final audits run,
  **then** both actual executables receive the same fresh audit batches.
- **Given** receipts for the wrong source, mismatched/reused inputs, search-phase
  work or unknown work, **when** promotion is attempted, **then** it fails closed.
- **Given** a failed selected program and a fully validated original, **when**
  fallback occurs, **then** the deployed hash identifies the audited original and
  normalized speedup is one.
- **Given** an original executable that fails a final audit, **when** deciding
  deployment, **then** the comparison fails without a deployable result, even if
  that original passed earlier diagnostic inputs. Failure receipts are retained.

## Archive boundary

`MapElitesArchive.TryAddWithMutation` checks completed status, quality, matching
candidate/evaluation identity and descriptor placement. It is not a general
program-correctness or feasibility oracle. The program host must map invalid
evaluations to failed status before archive admission. A search archive entry is
not equivalent to final deployment approval. No generic archive ranking/constraint
semantics are changed in this slice.
