## User story and acceptance criteria

**Priority:** P1. **Owner:** Evaluator maintainer. **Depends on:** US-03–US-05.

As a user optimizing runtime or model quality, I want robust evaluation so that a lucky timing or training run cannot create a false winner.

- [x] **Given** a promising candidate, **when** it challenges an incumbent, **then** repeated measurements and an independent confirmation run estimate the improvement and its uncertainty. Verified generic policy with separately owned callbacks; physical consumer independence remains caller-validated.
- [x] **Given** staged evaluation, **when** cheap screens reject candidates, **then** a predefined audit sample receives full evaluation to estimate false rejection of useful candidates. Verified explicit frozen-reject input, preselection, full replication and uncertainty including incomplete audits.
- [x] **Given** a request to remeasure fitness, **when** it runs, **then** cache policy permits fresh samples and all repetitions consume budget; descriptor-only `Remeasure` is not used as a substitute. Direct fresh dispatch and exact call charges verified, including warmups.

These checks describe the generic core contract, not full consumer deliverable approval. Actual production cascade
presets and representative noisy runtime/training comparisons remain unverified; issue #24 stays open.

Deliverable: noise-aware consumer evaluators, controlled warmup/timing protocols, and validated cascade presets. [Remeasure implementation](https://github.com/ooples/AiDotNet.Evolution/blob/f0f282cf2e9027ab5278a1953493c805d6ab52ad/src/AiDotNet.Evolution/Core/MapElitesArchive.cs).
