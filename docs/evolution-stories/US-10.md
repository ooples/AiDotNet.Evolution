## User story and acceptance criteria

**Priority:** P1. **Owner:** Performance maintainer. **Depends on:** US-01, US-04.

As a .NET developer, I want low orchestration overhead so that the engine remains useful when candidate evaluation is cheap.

- [x] **Given** pinned hardware and runtime settings, **when** engine operations are benchmarked, **then** throughput, allocations, peak memory, and checkpoint overhead are reported across archive sizes, island counts, and worker counts.
- [x] **Given** mixed evaluation durations, **when** batch and continuous dispatch are compared, **then** worker utilization and quality versus elapsed time are both reported.
- [x] **Given** deterministic evaluators and fixed semantic settings, **when** worker count changes, **then** determinism checks pass; continuous-mode comparisons explicitly fix `MaxInFlight`.

Deliverable: a BenchmarkDotNet project outside the shipping package. Engine throughput and resulting-algorithm speedup
are distinct measurements. These local engine profiles do not establish the latter.

Local verification: 47 profiling contract tests; all 661 core tests on each of net10.0, net8.0 and net471; successful
full solution formatting verification. The profiler records .NET 10.0.12, Windows build 26200, x64, CPU group/mask,
processor count, GC mode and runtime controls. Only owned child settings change; host frequency/power/background
load are not controlled. Lifetime peak working set includes startup/setup/warmup, and is distinct from managed allocation.

The [original 132-attempt campaign](../../benchmarks/evidence/performance/0bed72d-failed.json) remains failed: it incorrectly
grouped checkpoint-on/off runs into the same deterministic comparison. Continuous checkpoint drains change proposal
context and lineage; worker counts do match within each fixed checkpoint setting. The corrected report is a new full run,
not a rewrite of the failed result. Checkpoint timing includes queue-drain effects; batch and continuous saved different
checkpoint counts under the same configured interval. The evidence explicitly discloses this distinction.

Hosted CI and independent review must be evaluated on the pushed head; no approval is claimed by local tests or a
bot status alone. CI now tests profiling contracts, runs isolated smoke on Linux and uploads all raw diagnostics.
