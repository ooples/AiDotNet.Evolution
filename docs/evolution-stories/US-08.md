# US-08: Adapt proposal strategies using measured outcomes

Issue [#26](https://github.com/ooples/AiDotNet.Evolution/issues/26); core [#51](https://github.com/ooples/AiDotNet.Evolution/pull/51) on US-07 #50; companion [AiDotNet #2212](https://github.com/ooples/AiDotNet/pull/2212) on consumer US-06 #2210. Shared foundations are retained.

As a user, I want search to favor productive proposal strategies so that it spends less effort on ineffective mutations.

- [x] **Given** a portfolio of mutation, crossover, restart, local-refinement and consumer-provided LLM operators, **when** outcomes arrive, **then** selection uses valid improvement or archive success per declared total cost while retaining exploration. Costed consumer adapters and the compiler-arm factory preserve setup, parsing, compilation, repairs, audit and evaluation accounting. The ledger identity is shared, not just its unit label.
- [x] **Given** an operator produced a candidate, **when** evaluation commits, **then** typed credit identifies the operator/configuration, archive outcome and consumed proposal/evaluation costs once. In-process notifications are guarded against failures/reentry; they are not a transactional exactly-once external storage guarantee.
- [x] **Given** adaptive state, **when** a compatible run resumes, **then** learned history, pending attribution, child state and engine-owned random streams restore consistently. Core coordinated-boundary engine/ledger tests and consumer pending/future-proposal tests pass. Automatic facade resource resume remains refused rather than silently restoring an unrelated ledger.
- [x] **Given** the best static preset from the declared development candidates, **when** adaptation is evaluated, **then** useful gain must be statistically supported on different held-out tasks before becoming a default. The 1,152-run study completed; all six comparisons failed the promotion gate, so adaptation remains optional and no default changed.
