# US-17 — Compiler-guided program improvement

Issue: https://github.com/ooples/AiDotNet.Evolution/issues/35

All new implementation is owned by AiDotNet.Evolution. Base: US-08 / PR #51, retaining shared foundation #15.
Historical AiDotNet #2165 is a tracking-only draft, not this implementation and not authorization to keep features there.

As a developer optimizing an algorithm, I want planned edits and bounded repair so that more proposals become
correct, useful programs.

- **Given** an initial program and measured bottleneck, **when** improvement is proposed, **then** a testable hypothesis
  and syntax-addressed edits operate on a detached, fingerprinted multi-file snapshot.
- **Given** compilation or public correctness failure, **when** repair is allowed, **then** bounded diagnostics guide
  a finite repair loop, all dispatched work is charged, and no held-out feedback reaches the planner.
- **Given** a valid patch, **when** it is promoted, **then** compilation, preserved API contract, public correctness and
  held-out performance receipts identify the same source/dependency/compiled-image fingerprint.

Implementation: `src/AiDotNet.Evolution.Programs`, `src/AiDotNet.Evolution.CSharp`.
Acceptance/adversarial tests: `tests/AiDotNet.Evolution.CSharp.Tests`.
Real emitted-image integration: `examples/CompilerGuidedSearch`.
Contracts, trust boundaries and limitations: [compiler guide](../COMPILER_GUIDED_PROGRAMS.md).

Verification results will be attached after the final validation batch. No merge, publication, broad performance
claim or automatic issue closure is implied. Dependency integration and independent review remain merge gates.
