# US-14: Rank proposals using a surrogate model

Issue: [#32](https://github.com/ooples/AiDotNet.Evolution/issues/32).
Current delivery: non-draft [PR83](https://github.com/ooples/AiDotNet.Evolution/pull/83),
dependent on [PR82](https://github.com/ooples/AiDotNet.Evolution/pull/82).
Integrates PR56 at `b1876087709a138c7ad2dc8e3ac85c778c82b374` onto the current
US-13/US-03–08 stack, preserving newer accounting and domain fixes.

As a user with expensive evaluations, I want a learned approximation to rank
promising candidates so that I can test whether fewer full evaluations are wasted.

## Functional acceptance

- [x] **Given** fresh measured outcomes, **when** the surrogate ranks a pool,
  **then** it records predicted quality, uncertainty, model version, validation
  evidence and exploration; only true evaluations may become archive fitness.
- [x] **Given** insufficient data, weak calibration or unfamiliar candidates,
  **when** ranking is unreliable, **then** explicit fallback chooses a real
  candidate for subsequent measurement rather than promoting a prediction.
- [x] **Given** equal total cost caps, **when** ordinary and surrogate search are
  compared, **then** setup, training/calibration/validation, inference and rejected
  proposals are charged, and every archive winner has a true evaluation.

The optional `AiDotNet.Evolution.Surrogates` package supports net10.0, net8.0 and
net471 without a model-library dependency in the core. It provides a stateless
validated nearest-neighbor backend with detached models, disjoint genome-group
partitions, bounded work and an isolated PackageReference consumer check.
Observation acquisition is explicit; search-data validation is not sealed final
confirmation. The backend remains experimental and opt-in.

## Adversarial review

- Reject overlapping original sample IDs and bind sample provenance into model
  identities; repeated evidence must not become fictitious independent training.
- Preserve current post-dispatch budget-denial/unknown-work handling; do not
  overwrite newer resource work with the older story branch.
- Fix quality-support cancellation: constant upper-bound observations could
  predict zero for supports [-1e100,1], [-1e300,1e-100], [-1,1e-100]. Exact bound
  decoding and versioned model semantics now pass all three regressions.
- Reject negative synthetic losses and balanced negative stage charges in
  analysis; retain such rows as worst-support penalties, never favorable results.
- Retain historical/current gzip, raw and summary hash chains, corruption checks,
  all failed rows and independently owned prediction/validation objects.
