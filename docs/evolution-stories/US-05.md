# US-05 — enforce and reconcile the real search budget

Issue [#23](https://github.com/ooples/AiDotNet.Evolution/issues/23).
Implementation owner: AiDotNet.Evolution only.

## Delivery scope

This change builds on US-03 PR #75 and selectively reuses US-05 commits
`acfa665`/`2f5f338` from PR #48. It does not import PR #48's later US-06 changes.
PR #48 remains historical/shared work; no automatic closure, merge or replacement.
Its issue's original tracking-only/companion ownership descriptions are stale.

Core: deterministic wave admission, full per-stage totals, overrun-result rejection
and coordinated paused engine/ledger snapshots. These cover all ten generic stages,
including refinement, surrogate training/inference, novelty and persistence;
producer-specific resource enforcement is still required.

Warm Python comparison: one shared host accounting/admission layer for all six
controller tracks, per-operation receipts flushed before dispatch, fixed model-call
and container-attempt ceilings, independent reserved final-audit capacity, and
cross-checks against broker/sample receipts. This layer does not add a second charge
to a C# engine ledger: the host journal owns benchmark dispatch charges; the generic
C# ledger remains the reusable in-process API.

## Given / When / Then

- **Given** a producer exceeding its reserved maximum, **when** its actual receipt
  settles, **then** preserve all spending, stop admission and refuse its result.
- **Given** a bounded wave, **when** admission runs, **then** ordinal operation IDs
  determine acceptance, invalid waves mutate nothing and completion timing does
  not backfill denied work.
- **Given** either cascade refund policy, **when** screening rejects work, **then**
  screening/full-evaluation resource totals remain visible despite engine counters.
- **Given** a new warm plan, **when** it is prepared/executed, **then** account for
  repeats, original/selected diagnostics and eight final audit executions per track
  before allowing search; insufficient total capacity rejects the plan.
- **Given** either controller, **when** model or container work begins, **then**
  reserve under the same lock and flush its unique operation to the journal before
  dispatch. Pending reservations count against limits; denials invoke no producer.
- **Given** setup, controller execution, validation or failed work, **when** it runs,
  **then** retain its stage/owner and observed wall time; shared setup is not silently
  allocated to one competitor. Controller spans include nested work and must not
  be summed with child timings as total cost.
- **Given** missing usage, malformed observations or interrupted cleanup, **when**
  reconciliation fails, **then** preserve the charged attempt, mark uncertainty and
  stop further admission. No missing measurement is represented as a free call.
- **Given** missing/duplicate final sample charges, changed cumulative totals or
  missing setup stages, **when** v3 evidence is summarized or used as a predecessor,
  **then** reject it rather than infer a cheaper winner.
- **Given** a used registration/journal, **when** execution is attempted again,
  **then** refuse replay rather than restore budget from an old snapshot.

## Protocol and units

New execution requires `warm-head-to-head-v3`, `warm-budget-v1` and an explicit
`--container-limit` in addition to the model call ceiling. Counts carry across
registered partitions; changes require an explicit approval reference before the
next partition. Old v2 measurements remain historical/readable, not executable as
budget-verified v3 evidence. No historical experiment or sealed input is rerun.

The budget caps admitted **model invocations and container attempts**, not dollars,
subscription quota percentages or tokens. Attempt charges can be conservative if a
producer fails before starting a process. Completed token usage is observed; the
existing broker's token threshold rejects overspending results after receipt, but
is not a provider-enforced token maximum. CPU counters stop at the response probe;
memory is a peak, never a sum of consumed bytes. Per-container isolation/time/memory
limits remain enforced by the existing sandbox. This is not a hard cap on total
host CPU, memory, wall time or monetary spending.

The journal and report support auditability, not authenticated distributed billing
or automatic crash recovery. New-file refusal and the one-use registration prevent
local replay; trusted custody is required to prevent intentional evidence rollback.
Snapshot capture requires paused, settled work; it is not safe to restore after
unrecorded external spending. Fsync does not promise portable directory durability.
Administrative preflight, JSON persistence and orchestration overhead are not
separately metered resource stages; overall study elapsed time is diagnostic only.
