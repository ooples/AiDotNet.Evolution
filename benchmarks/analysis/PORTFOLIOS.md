python benchmarks/analysis/portfolio_study.py register benchmarks/AiDotNet.Evolution.Quality/bin/Release/net10.0/AiDotNet.Evolution.Quality.dll plan.json --count 32 --confirmation-count 512 --budget 64
python benchmarks/analysis/portfolio_study.py execute plan.json results development

Register after the final build. Protocol `portfolio-study-v2` pins binary/core and analysis hashes, budgets, methods, disjoint seeds and decision criteria before evaluation. One-use claims beside the plan prevent retrying the same registration in another directory. Preserve interrupted/failed runs. The low-level C# runner is not itself a registration or defense against a filesystem owner modifying evidence.

Four static operators—mutation, crossover, restart and two-candidate local refinement—are compared with the same portfolio using parent-improvement or archive-success reward, plus a uniform portfolio control. Every arm receives an initial trial; epsilon 0.2 preserves exploration thereafter (epsilon 1 for uniform). All methods use the same seeded genomes, archive, uniform-parent rule and total resource ceiling. **One cost unit is one proposal dispatch or objective invocation**, not money, equal CPU time or FLOPs. Refinement consumes two actual inner objective invocations plus its proposal dispatch (three units) before the final evaluation. Reservations cannot overspend. Budget exhaustion or a fixed engine attempt/proposal cap ends the run; unused budget is reported.

The driver runs the actual `EvolutionEngine`, shared-ledger portfolio factory and metered evaluator. It does not synthesize evaluations or manually invoke feedback. Its raw engine outcomes, typed credits, ledger receipts, observations and final elite cells are reconciled by the reporter. CPU time and wall time are separate descriptive measurements. Core tests cover coordinated engine/ledger replay and pending attribution. Consumer-provided model sources use the same public factory; a scripted model test proves accounting without live requests. No dependency on AiDotNet consumer code is required.

The separate `PortfolioWorkload` leaves US-07 workloads untouched. Fresh seeds and instance stream 19817 define shifted rippled quadratic → coupled absolute objectives; shifted square/sine → absolute/cosine expression targets; five-weight matrix product → L1 kernels. Kernels have exact correctness checks, one warmup and three timings. Program search is a bounded interpreted grammar, not unrestricted generated code. Kernel search-time best timings are selection-biased and do not prove incumbent speedups.

Select the highest mean-quality **static** method per family on development only. Freeze it before confirmation and compare both adaptive policies against it AND the uniform-mixture control, isolating learning from access to more operators. Twelve one-sided Hoeffding bounds on paired differences in [-1,1] split alpha 0.05 across two policies × three families × two controls. Both lower gains must exceed 0.02, with no failed runs, before promotion eligibility. The registered 32 development/512 confirmation seeds reduce the confirmation radius to approximately 0.146; small effects will remain inconclusive. Criteria cannot change after results. Reports include paired before/after quality, archive diversity, dispatch/objective counts, charged cost, CPU, wall time and failures. No default or OpenEvolve-superiority claim follows from this local study.

Typed `CreditCommitted` notifications identify each responsible child/configuration, terminal evaluation/generation, archive result, evaluator attempts and proposal/evaluator charges. Notification failures are counted and isolated; mutation/checkpoint reentry is rejected. Notifications are attempted once in-process and not replayed after restore: this is not an exactly-once external database transaction. Persist using run + evaluation identity with an idempotent sink when durable delivery is needed. Credit history/pending attribution and child state are checkpointed; randomness is supplied by engine-owned deterministic streams, not a hidden portfolio RNG. Persist the shared ledger with the corresponding engine boundary.
