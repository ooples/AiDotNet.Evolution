# V1-56 (#169): OpenEvolve 0.3.2 examples through `aidotnet-evolve run --openevolve-config`

Run at `e6abeea` with `benchmarks/external/openevolve_examples_smoke.py` against OpenEvolve 0.3.2 (`411fb59`) on
Windows 11, .NET 10 and Python 3.13.14. Raw results: `smoke.json`.

Each example runs for 3 iterations, unmodified: its own config, initial program and evaluator. A stand-in model
server replaces the paid endpoint by rewriting the model name, `api_base` and `provider` in a copy of the config. It
answers with the initial program. The venv had OpenEvolve's dependencies plus the light requirements the examples
list (scipy, matplotlib, scikit-learn, pykalman, PyWavelets, openai, tqdm, datasets, lxml, requests,
beautifulsoup4). Each example runs from the directory its own command uses: the repository root, or its own folder
when its `template_dir` is relative to that folder.

An example counts as passed only when at least one evaluation completed. A run that imported and finished but
scored nothing counts as a failure.

## The seven that do not run, and why

None of these is an importer gap. Each needs something the example itself requires, and OpenEvolve would need the
same thing.

| example | reason |
| --- | --- |
| algotune | Its evaluator loads tasks from the separate AlgoTune task registry ("Could not load affine_transform_2d task from AlgoTune registry"), plus a large dependency set (jax, torch, ortools, ...). |
| attention_optimization | Its evaluator shells out to LLVM's `mlir-opt` ("Required tool not found: mlir-opt"). |
| llm_prompt_optimization | Its evaluator scores prompts by calling a real model API with a real key. The sandbox passes no credentials to evaluators, by design. |
| mlx_metal_kernel_opt | Needs Apple MLX, which runs only on macOS on Apple silicon. |
| sldbench | Its `run.sh` supplies a per-task config (`configs/<task>.yaml`) and `EVAL_TASK_NAME`. The example folder has no config, and OpenEvolve's defaults configure no model. |
| symbolic_regression | Its tasks are generated by `data_api.py` from a downloaded benchmark dataset. The folder holds no initial program or evaluator until then. |
| tsp_tour_minimization | Needs a C++ build (`g++ ... -o bin/runner`) and its own driver, `start_evolution.py`, around a multi-file program directory. |

## What this run fixed

The first run passed 13 of 21, but under a weaker rule: a run that finished without completing any evaluation
counted as passed. Fixes since then:

- **Evaluator output corrupted results.** Evaluators print progress to stdout. When that text contained a brace (a
  dict, a format string), the result JSON the shim printed could not be parsed (circle_packing). The shim now points
  stdout at stderr while the evaluator runs, at the descriptor level, so processes the evaluator starts are covered
  too.
- **Configs only PyYAML accepts crashed the CLI** (attention_optimization's quoted multi-line system message). They
  are now read with PyYAML, which is what OpenEvolve uses.
- **An evaluator timeout past the sandbox ceiling was refused** (arc_benchmark sets 180,000 s). It is now capped with
  a note, and the ceiling itself rose from 1 h to 24 h.
- **A negative `early_stopping_patience` was refused** (arc_benchmark). OpenEvolve reads it as "stop when the fitness
  reaches `convergence_threshold`", and it now maps to a target fitness.
- **`language: text` was refused** (llm_prompt_optimization). A language without dedicated support is now evolved
  as generic text.
- **A relative `template_dir` was resolved against the config file** (lm_eval). OpenEvolve resolves it against the
  working directory, and so does this now.
- The smoke finds each example's files by the names OpenEvolve accepts (`config.yml`, `init_program.py`, a prompt
  `.txt`), and routes `claude_code` providers to the stand-in (claude_code_quickstart).

## Reproduce

```text
dotnet publish src/AiDotNet.Evolution.Cli -c Release -f net10.0 -o <cli>
python benchmarks/external/openevolve_examples_smoke.py --upstream <openevolve checkout at 411fb59> \
    --cli <cli>/aidotnet-evolve.dll --python <venv python> --output smoke.json
```
